actionFrameInput(this, IO80211Buffer *buffer, u32 channel, void *hdr, u64 headerLen)
  - The 5th argument is the apple80211_act_frm_hdr length, NOT the frame length.
    memmove(queueEntry+0x10, hdr, headerLen) with cmpq $0x49/ud1 trap when
    headerLen >= 0x49 (RIP 0x220e8a5, the b248 panic). isValidAF rejects
    headerLen <= 0x47. So headerLen must be exactly 0x48.
  - Queue entry is 0x68 bytes: +0x00 buffer, +0x08 channel, +0x10 hdr copy
    (0x48), +0x58 headerLen, +0x60 mach_absolute_time. Ring at ivars+0x41c8,
    head 0x41d0, tail 0x41d4, mask 0x41dc, count 0x41e0.
  - Enqueue branch (0x41f0 bit0 set, 0x3ee0 bit1 set, 0x19e bit0 clear, ring
    not full) returns WITHOUT buffer->returnBuffer: ownership transfers to the
    family queue. Every other branch calls buffer->vtable+0x118
    (IO80211Buffer::returnBuffer). Return value is 0 on every path.
  - Therefore the driver must never touch or free the buffer after the call.
  - IO80211Buffer vtable (object vptr = __ZTV+0x10, verified from
    __DATA __const, chained target = 0xffffff8000100000 | t36):
    +0x118 returnBuffer, +0x130 getLength, +0x150 const getCursor,
    +0x158 getBytesNoCopy, +0x178 writeBytes, +0x140 getCapacity.
    getCursor returns {bytes, min(getLength, getCapacity)}.

Buffer content (isValidAF + actionFrameHasCorrectOUI)
  - cursor length must be >= 0x10.
  - bytes[1..3] = 00 17 f2, bytes[4] = 0x08, bytes[5] (version) must be
    NONZERO (version 0 takes the "bad oui" log and returns false).
  - bytes[0] is the vendor category 0x7f (not compared). So the buffer holds
    the Action body starting at 0x7f, not the 802.11 header.

1.2.1 implementation
  - RX handoff: copy the 72-byte metadata with the frame capture, build the
    pool buffer from the Action body at the 24/28-byte 802.11 offset, and call
    actionFrameInput(manager, buffer, channel, metadata, 0x48). Buffer is
    never returned or touched afterwards. Skips when the OUI/version or RSSI
    is missing (rssi 0 cannot create a peer).
  - MI TX: slots 41/50 validate version, length (<=0x4b0), that the frame
    pointer equals manager+0x2358 and that manager+0x2808 low16 matches, copy
    the TLV payload, then transmit it as a broadcast MIF (subtype 3) inside the
    engine's currently granted window with the window's TxContext. The ack is
    returned only after submitAwdlDiscovery published the descriptor; no
    window or wrong peer channel => EAGAIN, no fake success.
